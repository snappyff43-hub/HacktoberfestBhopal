  - **Language:** Hindi / Hinglish.

#### C. Errors Encountered & Architectural Fixes
- **Issue:** Initially, passing `"format": "json"` to Ollama on CPU caused severe constrained BNF grammar decoding bottlenecks, triggering a `TimeoutError (>120s)`. Additionally, `gemma4` utilizes a native `thinking` capability where reasoning tokens precede final content.
- **Fix Implemented:**
  1. Removed constrained grammar decoding in favor of unconstrained high-throughput generation.
  2. Set `num_thread: 4` in payload options to maximize Intel i5-1235U performance cores.
  3. Added intelligent thinking-stream inspection in `gemma_service.py` to extract structured JSON blocks even when reasoning tokens are present.
  4. Increased HTTP client timeout to 180 seconds.

#### D. Errors Encountered & Architectural Fixes
- **Issue 1:** `gemini-2.5-flash` returned `404 NOT_FOUND` indicating the model endpoint has transitioned to `gemini-3.8-flash` for new requests.
- **Issue 2:** `gemini-3.8-flash` occasionally encounters high-demand spikes (`503 UNAVAILABLE`) on Google endpoints.
- **Issue 3:** Printing Devanagari Hindi text to Windows console resulted in `UnicodeEncodeError: 'charmap' codec can't encode characters`.
- **Fix Implemented:**
  1. Built resilient multi-model fallback cascade in `gemini_service.py` prioritizing `gemini-flash-lite-latest` and `gemini-2.5-flash-lite` for instant sub-2s responses, with `gemini-3.8-flash` as backup.
  2. Configured `sys.stdout.reconfigure(encoding="utf-8")` to guarantee flawless Devanagari Unicode rendering across Windows terminals.
